## 两个窗口：调试内核和手动验证页表

A 窗口：make debug
A 没有输出很正常，因为 -S 让模拟 CPU 等待。

B 窗口同样进入 code 目录：make gdb
若报 riscv64-unknown-elf-gdb 找不到，使用：
gdb-multiarch -q bin/kernel
set architecture riscv:rv64
target remote localhost:1234

下面均输入在 (gdb) 后：
set pagination off
hbreak *0x80200000
continue
p/x $pc
p/x $satp

物理入口应为 0x80200000，satp 应为 0。
delete breakpoints
hbreak kern_init
continue
p/x $pc
p/x $satp

此时已进入高虚拟地址。当前构建 kern_init 为 0xffffffffc02000d6。
set $va = (unsigned long long)&kern_init
set $root = ($satp & 0xfffffffffff) << 12
p/x $root
p/d ($va >> 30) & 0x1ff
p/d ($va >> 21) & 0x1ff
p/d ($va >> 12) & 0x1ff
p/x $va & 0xfff

当前结果：root=0x80205000，VPN2=511，VPN1=1，VPN0=0，offset=0xd6。
set $pt = (unsigned long long *)&boot_page_table_sv39
set $pte = $pt[511]
p/x $pte
p/x $pte & 0xff

PTE=0x200000cf，低位 0xcf 表示 V/R/W/X/A/D=1。
R/X 非零说明这里已经是叶子，根层叶子映射 1 GiB，不往下查两层。
set $pa = (($pte >> 28) << 30) | ($va & 0x3fffffff)
p/x $pa
x/4i $va
monitor xp /4i 0x802000d6

本次 PA=0x802000d6；虚拟地址与物理地址处的指令应一致。
如构建地址变化，最后一条命令要换成刚刚 p/x $pa 输出的数。

## 看分配器检查调用栈

delete breakpoints
hbreak best_fit_check
continue
bt
list best_fit_check
p 'best_fit_pmm.c'::free_area.nr_free

nr_free 是宏，GDB 中不要 p nr_free；宏不一定保留在调试信息中。
-O2 可能使源码行显示在 list.h，这是内联优化，不代表停错函数。

## GDB 常用键

c：继续直到下个断点；si：执行一条机器指令；ni：执行一条，不进入调用；
n：执行一行 C，不进入函数；s：执行一行并进入函数；
p/x：十六进制打印；x/8i $pc：反汇编；bt：调用栈；
Ctrl+C：暂停被调试目标；q：退出 GDB。
退出时可在 GDB 输入 monitor quit（结束 QEMU），再 q。

## 需要当场讲清楚

以上两个窗口只观察了内核和手工核验页表。
指导书还要求三个窗口、两个 GDB：一个调试 QEMU 的宿主机源码，一个调试 RISC-V 内核。
不能把上述演示声称为已单步进入 QEMU 页表遍历函数。

指导书 QEMU 4.1.1 的源码关键点：
target/riscv/cpu_helper.c：riscv_cpu_tlb_fill -> get_physical_address -> tlb_set_page
accel/tcg/cputlb.c：load_helper/store_helper 的 tlb_hit 检查及 tlb_fill。
取指也可从 get_page_addr_code 的检查进入；TCG 快路径可能直接生成宿主指令，不能说每次都调用 C 的 load_helper。

具体完整双 GDB 步骤见本次答复和后续验证材料。
